Wiki & Other Information

Welcome to filer, an Open Source and Free media sharing service.

Because this is a small scale project ran by a single individual, there is quite a bit that goes into using this software. With that being said, I felt it would be of importance to highlight various features as well as outline instructions for using filer.

Self-hosting

Because filer is complete Open Source, users are recommended to self-host this service if they want. However it isn't necesarily straightforward and takes a level of technology literacy to get working, please read the following if that interests you:

Required Software

  • Git
  • NodeJS
  • ffmpeg
  • PostgreSQL
  • TypeScript

Instructions

  1. Clone the project by running git clone https://github.com/lill1e/filer.git
  2. Change directories by running cd filer
  3. Install the node packages by running npm install
  4. Open PostgreSQL by running psql
  5. Setup the Database by running \i db.sql
  6. Exit psql by running exit
  7. Run filer by running npm run test

Command Line Utility (filer-client)

While the service contains quite a few features via endpoints, it can admittedly be tedious to use. To adjust to that issue, there is a client available in the repository for ease of use. The client requires that a token be passed via the --token flag. With the client you can use the --path flag to provide a video to upload, completely avoiding the need of knowing the specifics of the upload schema.

Server Endpoints

filer opens up various endpoints that can be used for interaction with this service (some more useful than others). Below is a list of each endpoint with a description of what they do.

  • GET / — The root directory, shows the home page
  • POST /auth — Given a valid auth code, this creates a new session for the corresponding users
  • GET /token — Returns the user's token in a raw string
  • GET /refresh — Refreshes the current session token and updates the cookies
  • GET /logout — Ends the current session, clears current cookies
  • POST /upload — Uploads a given video, given a correct payload
  • GET /clips/:clip — Shows a specific upload in a user friendly format
  • GET /raw/:clip — Displays the raw video file of a requested video
  • GET /thumbnail/:clip — Displays the thumbnail of a requested video
  • POST /clips/:clip/edit — Reuploads a video with specific flags passed to modify the video (e.g. cropping or trimming)
  • POST /clips/:clip/visibility — Toggles the visibility of an upload
  • GET /operations — Displays the operations in JSON format
  • GET /operations/:operation — Displays data about a sepcific operation in JSON format
  • GET /admin — Displays the current processing uploads in a user-friendly table

.env Spec

filer uses a .env file to pass sensitive data to the server at runtime. These fields are required for filer to operate and are below for use of constructing the configuration file.

  • PORT (e.g. 3000)
  • DATABASE_HOST (e.g. localhost)
  • DATABASE_PORT (e.g. 5432)
  • DATABASE_USER (e.g. postgres)
  • DATABASE_PASSWORD (e.g. password)
  • DATABASE_NAME (e.g. filer)
  • DATABASE_CLIENT_ID (Application ID from Discord Developer Portal)
  • DATABASE_CLIENT_SECRET (Client Secret from Discord Developer Portal)
  • DATABASE_REDIRECT_URL (e.g. http://localhost:3000/auth)
  • BASE_URL (e.g. http://localhost:3000)
  • JWT_SECRET (Some string used for encrypting Session Tokens)
  • DISCORD_WEBHOOK (Discord Webhook URL to log uploads to)
